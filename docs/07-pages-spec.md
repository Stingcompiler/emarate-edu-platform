# مواصفة الصفحات — Pages Specification

> إصدار 1.0 — 2026-09-27. خريطة كل صفحة في الموقع العام والبوابة، بما يكفي لبنائها من `06-design-system.md` دون قرارات إضافية. الصلاحيات من `03-roles-and-permissions.md` v2.1.

الترميز في الجداول: **الكتل** = المكوّنات بالترتيب من الأعلى؛ **البيانات** = مصدر الـ API؛ **الإجراءات** = ما يفعله المستخدم.

### 2.2 الهيكل المشترك
TopBar: شعار (mark + اسم)، بحث نطاقي، جرس الإشعارات، لغة، قائمة المستخدم (الملف، الإعدادات، خروج). Sidebar: قائمة الدور (§2.3–2.15)؛ عند تعدد الأدوار تُدمج المجموعات بعناوين. صفحات مشتركة لكل الأدوار: `/notifications`, `/profile`, `/settings` (تفضيلات الإشعارات، اللغة، كلمة المرور، الأجهزة/Push)، `/regulations` (للطلاب)، `/help`.

### 2.16 الأدوار الإدارية على الهاتف (09 §2.3)
Drawer بالقائمة الكاملة + تبويبات: الرئيسية / الإشعارات / أنا. شاشات هاتف مخصصة (قوائم مجمّعة + Sheets) لـ: اعتماد طلبات التسجيل، تولّي/مراجعة طلب تقديم (حالة، مستندات، رسالة)، الرد على استفسار (بريد/WhatsApp)، الموافقة على تعديل نتيجة، إرسال إشعار، إنشاء إعلان/فعالية سريعة. الشاشات التالية تعرض على الهاتف رسالة "أكمل من الحاسوب": الاستيراد (طلاب/نتائج)، منشئ نماذج التقديم، محرر الصفحات، التقارير الكبيرة، إنشاء الاختبارات الكاملة.

## 3. قواعد عامة للصفحات
1. كل صفحة قائمة: `PageHeader` + `FilterBar` + `Table/CardList` + `Pagination`، الفلاتر في URL.
2. كل صفحة كيان: Header بحالة + إجراءات من `allowed_transitions` + تبويبات + تبويب "السجل".
3. كل نموذج إنشاء معقّد (تقديم، اختبار، واجب، استيراد، تحويل) = Wizard بحفظ مسودة.
4. الحذف متاح فقط حيث تسمح المصفوفة، وبتأكيد.
5. الطالب لا يرى أي صفحة تخص طالبًا آخر؛ كل الروابط بـ `public_id` حيث تُشارك.
6. كل صفحة تعمل على 375px عرضًا؛ الجداول تتحول لبطاقات.
7. أي بيانات تُعرض من الخادم بلا افتراضات في الواجهة (لا قوائم ثابتة للأقسام/البرامج/الحالات).
