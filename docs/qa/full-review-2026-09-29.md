# مراجعة شاملة للمشروع — 29 سبتمبر 2026

بطلب المالك: مراجعة المشروع كله بدءًا بالموقع العام ثم البوابة؛ التأكد أن المنطق والدخول والصلاحيات تعمل؛ ثم فحص التصميم وتجربة المستخدم بمعايير حديثة على الهاتف والشاشات الكبيرة، وأين تفيد الحركة؛ ثم خطة تنفيذ تشمل كل الإصلاحات.

## 1. خطة المراجعة

**البيئة:** بيئة الاختبار (`pnpm e2e`: API ‎:8001، البوابة ‎:5174، الموقع ‎:4322) ببيانات العرض كاملة مولّدة من جديد، وكل الحسابات الأربعة عشر (`<role>@demo.ecst.test` والطالب `26-IT-0001`). لا تُمس بيانات التطوير.

**المقاسات:** 390×844 (هاتف)، 768×1024 (لوحي)، 1280×800، 1440×900، 1920×1080. الوضعان الفاتح والداكن للبوابة.

### المرحلة أ — الموقع العام (زائر)
1. كل صفحة يمكن الوصول إليها من `/ar/` و`/en/`: تعمل، بلا روابط مكسورة ولا تمرير أفقي ولا أخطاء سكربت.
2. الرحلات: الرئيسية ← البرامج ← برنامج ← «قدّم»؛ القبول؛ الأخبار والفعاليات والإعلانات؛ التواصل (إرسال + متابعة بالرقم المرجعي)؛ التقويم؛ اللوائح؛ الصفحات الرسمية؛ تبديل اللغة؛ 404.
3. الواجهة: مقارنة بلوحات النموذج الأولي، التسلسل البصري، الخطوط والمسافات، الصور، الحالات الفارغة، الحركة (تظهر ولا تخفي محتوى)، SEO والوصولية.

### المرحلة ب — الدخول والصلاحيات
1. الدخول بالبريد وبالرقم الجامعي، كلمة مرور خاطئة، القفل بعد المحاولات، الخروج، انتهاء الجلسة وتجديدها، التفعيل، نسيت كلمة المرور، التسجيل، زائر بـ OTP (التقديم والمتابعة).
2. كل مسار في البوابة بلا دخول ← يعود إلى صفحة الدخول ثم إلى الصفحة المطلوبة بعده.
3. كل دور يفتح مسارات الأدوار الأخرى ← رسالة «غير مسموح» بلا بيانات ولا انهيار؛ والخادم يرفض (مصفوفة الصلاحيات `core/tests/test_permission_matrix.py` + فحص القسم في `test_department_scope.py`).
4. الكوكيز والحماية: HttpOnly، SameSite، CSRF على كل كتابة، لا بيانات حساسة في الروابط.

### المرحلة ج — البوابة دورًا دورًا
لكل دور: كل صفحة في قائمته وكل صفحة تفصيلية يصل إليها، ثم رحلات العمل الأساسية:

| الدور | الرحلات |
|---|---|
| الطالب | اليوم، موادي ← مادة ← محاضرة، واجب ← تسليم، اختبار ← نتيجة، نتائجي وكشف الدرجات، الإشعارات، الإعدادات، التثبيت |
| الأستاذ / المعيد | محاضرة جديدة ← نشر، واجب ← تصحيح، اختبار ← مراقبة ← إحصاءات، بث، إعلان، دفتر الدرجات |
| مدير / مشرف القسم | اللوحة، المواد (تعيين/تعديل/حذف)، المحاضرات، الأساتذة، الطلاب (إضافة/تعديل/حذف)، الموافقات، التقارير، النتائج، السجل |
| مسؤول المسجلين / المسجل | الطلبات ← مراجعة ← قرار ← تسجيل، الدورات والقوالب، سجل الطلاب والاستيراد، الاستفسارات |
| مسؤول النتائج | رفع ملف ← معاينة ← اعتماد ← نشر، البحث، طلب تعديل، الإعدادات |
| أمين الشؤون العلمية | الأقسام والقيادات، الموافقة على تعديل النتائج، تقارير الأساتذة |
| أمين شؤون الطلاب | اللوائح، الحالات، البلاغات، إيقاف طالب |
| الموارد البشرية | ترتيب الأداء، ملف أستاذ، تنبيه |
| مدير الموقع / الفعاليات | الصفحات والأخبار والوسائط والقوائم والتحويلات، الفعاليات |
| مدير النظام | المستخدمون والأدوار، الهيكل، الإعدادات، التدقيق |

لكل صفحة: أخطاء السكربت، طلبات API الفاشلة، التمرير الأفقي، الوصولية (axe، WCAG AA)، ثم لقطات على المقاسات الخمسة للمراجعة البصرية.

### المرحلة د — التصميم وتجربة المستخدم
المعايير: نظام التصميم (docs/06)، مواصفات الصفحات (docs/07)، لوحات النموذج الأولي (هاتف 390، سطح مكتب 1280)، وقواعد حديثة: وضوح التسلسل، هدف لمس ≥ 44px، حالات التحميل والفراغ والخطأ، رسائل عربية مفهومة، اتساق المكونات، استغلال الشاشة الكبيرة (لا عمود هاتف في وسط شاشة عريضة)، الوضع الداكن، الحركة حيث تفيد (تغذية راجعة، انتقالات، أرقام) لا حيث تشتت.

### المرحلة هـ — خطة التنفيذ
كل ملاحظة ← أولوية (🔴 عالية: تمس الصحة أو الأمان أو التقديم · 🟠 متوسطة · 🟢 تحسين)، ثم تجميعها في PRs صغيرة مرتبة، لكل PR: الملفات، الاختبارات، والتحقق على المقاسين.
