# نظام مراجعة الجودة الآلي — OpenCode

نظام يحوّل طريقة المراجعات السابقة في `docs/qa/` إلى أمر واحد قابل للتكرار: `/qa`. يحدد ما تغيّر،
ويوزّع العمل على نماذج Claude حسب صعوبته، ويثبت كل خلل بمجس، ثم يكتب تقريرًا بنفس صيغة
`comprehensive-review-2026-10-08.md`.

**المبدأ:** النموذج لا يشغّل الاختبارات بنفسه ولا يقرأ السجلات كاملة. السكربتات تعمل بلا tokens؛
النموذج يخطط، ويكتب المجسات، ويحكم على النتائج.

## 1. المكوّنات

```
opencode.json                     النموذج الافتراضي Sonnet، والصغير Haiku
.opencode/
  agents/
    qa-lead.md                    Sonnet · المنسّق: النطاق، التوجيه، التقرير (primary)
    qa-logic-auditor.md           Opus   · تدقيق المنطق في المناطق الخطرة (قراءة فقط)
    qa-probe-writer.md            Sonnet · يحوّل الفرضيات إلى مجسات ويشغّلها
    qa-ui-auditor.md              Sonnet · الصفحات مقابل اللوحات، على 390 و1280 و1440
    qa-runner.md                  Haiku  · يشغّل الفحوص ويصنّف الأعطال
  skills/                         تُحمَّل عند الحاجة فقط (autoinvoke=false)
    qa-demo-data   الحسابات التجريبية، fixtures، والشخصيات التي تكشف الأخطاء
    qa-probes      كتابة المجسات وتشغيلها (نفس منهج مراجعة 8 أكتوبر)
    qa-journeys    رحلات E2E حقيقية: الأدوار، انقطاع الشبكة، الساعة، الهاتف
    qa-ui          التقاط الشاشات والحكم عليها
    qa-report      صيغة التقرير وملف الأدلة
  commands/
    qa.md          /qa [diff|full|<منطقة>|--base <ref>]
    qa-verify.md   /qa-verify <review-id>  — هل أُصلحت بنود مراجعة سابقة؟
scripts/qa/                       حتمية، بلا AI
  scope.py         ما تغيّر، المناطق الخطرة، الفحوص المقترحة، قرار التوجيه
  run.sh           يشغّل الفحوص ويحفظ السجل كاملًا ويطبع ملخصًا ≤ 25 سطرًا
  probe.sh         ينسخ المجس مكانه، يشغّله على SQLite/PostgreSQL، يحفظ السجل، يحذف النسخة
  capture.config.ts + capture/   لقطات الصفحات واللوحات + فحص التمرير الأفقي وaxe
```

الملفات الموجودة تبقى كما هي: `CLAUDE.md` يقرؤه OpenCode تلقائيًا (لا يوجد `AGENTS.md`)، و
`.claude/skills/responsive-page` يقرؤه وكيل الواجهة. **لا تنشئ `AGENTS.md`** وإلا توقف OpenCode
عن قراءة `CLAUDE.md`.

## 2. دورة `/qa`

1. `scope.py` يعمل داخل الأمر نفسه (بلا tokens): الفرق منذ آخر تقرير مراجعة، والتطبيقات الخطرة،
   وإشارات الخطر في الأسطر المضافة (أقفال، صلاحيات، جلسات، ساعة، طابور دون اتصال، ترحيلات)،
   والفحوص المقترحة، وقرار التوجيه.
2. `qa-runner` (Haiku) يشغّل خط الأساس عبر `run.sh` ويصنّف كل فشل: انحدار، بيئة، متقطع، معروف.
3. بالتوازي: `qa-logic-auditor` (Opus) إن كان النطاق خطرًا، و`qa-ui-auditor` إن تغيّرت واجهة.
4. `qa-probe-writer` يكتب مجسًا لكل فرضية في `docs/qa/evidence/<id>/` ويشغّله عبر `probe.sh`.
5. `qa-lead` يكتب `docs/qa/<id>.md` وملف أدلة README. فقط ما ثبت بمجس أو بملاحظة مباشرة يأخذ رمزًا.

بعد الإصلاح: `/qa-verify review-…` يعيد تشغيل المجسات. المجس يتوقع الخلل، فإذا **فشل** فالخلل زال.

## 3. قواعد التوجيه بين النماذج

| العمل | النموذج | السبب |
|---|---|---|
| تشغيل الفحوص، قراءة السجلات، تصنيف الأعطال | Haiku 5.5 | عمل آلي، حجم كبير |
| التنسيق، كتابة المجسات، مراجعة الواجهة، التقرير | Sonnet 5.5 | توازن بين الذكاء والتكلفة |
| تدقيق المنطق: الصلاحيات، المعاملات والأقفال، حالات السجلات، الاختبارات، النتائج، المزامنة | Opus 5.5 | أخطاء خفية مكلفة إن فاتت |

**متى يُستدعى Opus:** يقرر `scope.py` ذلك وليس النموذج: عند تغيّر تطبيق من
`accounts, admissions, exams, results, students, student_affairs, core, files, audit`، أو ظهور
إشارة أقفال/صلاحيات/جلسات/مزامنة. غير ذلك يكفي فحص خفيف من Sonnet.

**التصعيد:** مجس «غير واضح» مرتين ← يعود إلى Opus مرة واحدة فقط ← وإلا يُكتب «لم يثبت».
أي اشتباه P0 لا يُكتب P0 قبل مجس يثبته. الحد: استدعاءان لـ Opus في الجولة (3 في `full`).

Fable 5.1 غير مستخدم عمدًا؛ أغلى بمرتين ونصف من Opus، ويُستدعى يدويًا فقط لتحقيق نادر وطويل.

## 4. تقليل استهلاك الـ tokens

| الأسلوب | أين | الأثر |
|---|---|---|
| السكربتات تعمل بدل النموذج | `scope.py`, `run.sh`, `probe.sh`, capture | الأكبر: الفحوص والسجلات بلا tokens |
| ملخص ≤ 25 سطرًا والسجل الكامل على القرص | `run.sh` | سجل pytest كامل قد يكون عشرات آلاف الـ tokens |
| النطاق بالفرق منذ آخر تقرير | `scope.py` | لا يُقرأ إلا ما تغيّر |
| Opus بقرار حتمي وبحد أقصى | `scope.py` + `qa-lead` | أغلى نموذج يعمل حيث يستحق فقط |
| الـ skills لا تظهر إلا بالاسم | `autoinvoke: "false"` | جلساتك العادية لا تدفع ثمن قائمة QA |
| حد الخطوات `steps` لكل وكيل | ملفات الوكلاء | يمنع الحلقات الطويلة |
| مخرجات بصيغة ثابتة قصيرة | كل وكيل | لا شرح، سطر لكل نتيجة |
| تعليمات الوكلاء بالإنجليزية والتقرير بالعربية | الوكلاء والـ skills | النص العربي يستهلك tokens أكثر للمعنى نفسه |
| حد للصور: 24 صورة | `qa-ui-auditor` | الصور أغلى مدخلات المراجعة البصرية |
| لا محتوى ملفات في رسائل الوكلاء، مسارات وأسطر فقط | `qa-lead` | لا يتكرر النص نفسه في أكثر من سياق |

**تكلفة تقديرية** بأسعار API الحالية (Opus $4/$20، Sonnet $2/$10 لكل مليون token إدخال/إخراج):
جولة `diff` عادية تقريبًا 1–3 دولار، وجولة `full` تقريبًا 5–10 دولار. تقدير وليس قياسًا؛ راقب
الاستهلاك في أول جولتين وعدّل الحدود.

## 5. الأثر المعماري

**ما يكسبه المشروع:**
- مراجعة تتكرر مع كل مرحلة بدل مراجعات يدوية متباعدة، وبنفس المنهج والصيغة.
- كل خلل مثبت يتحول إلى اختبار انحدار دائم، فتكبر التغطية في المناطق التي فشلت فعلًا.
- قرارات التوجيه في سكربت مقروء ومراجَع، لا في مزاج النموذج.

**ما يفرضه على الكود (وأغلبه موجود):**
- `seed_demo` حتمي وقاعدة E2E تُبنى من الصفر في كل تشغيل — موجود.
- محددات بالدور والاسم العربي في Playwright — موجود؛ أي تغيير لنص زر يكسر رحلات.
- الصلاحيات في مكان واحد (`accounts/rbac.py`) ومصفوفة الصلاحيات — موجود، وهو ما يجعل تدقيق
  النطاق ممكنًا.
- منافذ E2E مستقلة (8011/5184/4332) حتى لا تتعارض مع `pnpm dev`.

**التكاليف والمخاطر:**
- صيانة: `scope.py` يعرف أسماء التطبيقات والمواصفات؛ تطبيق جديد يحتاج سطرًا فيه.
- ثقة زائفة: تقرير بلا بنود لا يعني منصة بلا أخطاء. الحدود تُكتب في كل تقرير.
- المجسات تُكتب بالذكاء الاصطناعي: راجع أول دفعة بنفسك قبل أن تعتمد صيغتها.
- لا يختبر الإنتاج ولا الحمل ولا الأجهزة الحقيقية؛ هذه تبقى على المالك.

## 6. التشغيل لأول مرة

1. ثبّت OpenCode، ثم `opencode auth login` واختر Anthropic بمفتاح API (اشتراك Pro/Max لا يغطي
   الأدوات الخارجية).
2. `opencode models | grep anthropic` وتأكد أن المعرّفات في `opencode.json` وملفات الوكلاء موجودة.
3. اختياري لـ PostgreSQL: `export QA_PG_URL=postgres:///ecst_qa` (قاعدة محلية فقط؛ `run.sh`
   يرفض أي عنوان يشبه الإنتاج).
4. من جذر المستودع: `opencode`، ثم بدّل إلى الوكيل `qa-lead` (Tab) أو اكتب مباشرة `/qa`.
5. أول جولة: `/qa accounts` لتجربة صغيرة، ثم `/qa` عادية بعد كل مرحلة.

## 7. ما لا يفعله النظام

لا يعدّل كود التطبيق، لا يدمج ولا يرفع ولا ينشر، لا يلمس `*.stingdev.pro`، ولا يستبدل مراجعة
المالك لنتائجه.
