## نطاق الجولة الكاملة وطريقة تنفيذها

تبدأ المراجعة بجرد النسخة قيد الفحص وتتبع رحلاتها من الواجهة إلى الخادم. تُستخدم المحاور 0–9 أدناه للتعمّق في تغييرات نوفمبر، وتضاف شروط التغطية الواردة هنا إلى معيار الإغلاق في §7. البنود التالية خطة تنفيذ؛ تُسجّل النتائج عند الفحص.

### 1. تثبيت ما يدخل في المراجعة

يثبّت مسؤول الجودة معرّف النسخة وبيئة الاختبار وتاريخها. يستخرج قوالب صفحات الموقع من `apps/landing/src/pages` بما فيها الصفحات الديناميكية، ومسارات البوابة من `apps/portal/src/main.tsx` وقواعد عرضها من `ROUTE_ACCESS`. يطابقها مع [مواصفة الصفحات](../07-pages-spec.md) ومع وحدات Django المسجّلة ومسارات API ومخطط OpenAPI. يشمل الجرد المسارات المباشرة والطباعة وصفحات الخطأ وما يظهر بعد فتح نافذة أو اختيار سجل.

| سجل التغطية | وحدة العد | البيانات التي تُحفظ لكل صف |
|---|---|---|
| الموقع العام | قالب × لغة | المسار، مثال منشور، حالة بلا محتوى، مصدر البيانات، الإجراء الرئيسي |
| البوابة | مسار × دور ينطبق عليه | نقطة الدخول، النطاق، الحالة المطلوبة، العملية المتوقعة وما يراه المستخدم بعدها |
| الخادم | وحدة × عملية عمل | المستدعي، الخدمة، البيانات المقروءة والمكتوبة، الصلاحية، الأثر المؤجل، الاختبار |
| فحص العرض | صفحة × حجم مطلوب | الجهاز والمتصفح والاتجاه والتكبير، نتيجة فحص الحدود، رابط اللقطة أو العيب |

تُعلَّم الصفحات الموجودة في الكود فقط، والمواصفات بلا تنفيذ، والمسارات التي تحتاج بيانات خاصة. تُستخدم حسابات تجريبية لقسمين، ومستخدم متعدد الأدوار، وسجلات فارغة وممتلئة وبأسماء طويلة. يُسجّل لكل حالة «ناجح، فاشل، متعذر، غير منطبق» مع سبب الحالتين الأخيرتين.

### 3. رحلات تكشف أعطال الربط بين التطبيقات

تُنفَّذ الرحلة من نقطة دخول المستخدم حتى أثرها عند الطرف الآخر، ثم يُعاد فتح الصفحة للتحقق من بقاء النتيجة. يستكمل الجرد بقية المسارات، حتى الصفحات التي لا تمر بها هذه الرحلات.

| المستخدم والسطح | الرحلة | النتيجة التي يحسم بها الفحص |
|---|---|---|
| زائر الموقع العام | الرئيسية ← قسم ← برنامج ← تقديم ← متابعة الطلب. تتكرر الرحلة بالعربية والإنجليزية وعند إغلاق القبول. | يبقى البرنامج صحيحًا عند الانتقال، ويفهم الزائر حالة الطلب أو سبب إغلاق التقديم. تُراجع روابط اللغة وبيانات SEO على البناء النهائي. |
| مدير الموقع والفعاليات | تحرير محتوى أو فعالية ثم النشر وسحب النشر؛ مراجعة الأخبار والتقويم والكوادر والصور وصفحات المحتوى. | يظهر التغيير في الموقع العام بعد دورة البناء، وتُحترم خصوصية الكادر وحالة النشر في اللغتين. |
| طالب وأستاذ ومعيد | التسجيل أو التفعيل ← «اليوم» ← مقرر ← محاضرة أو بث ← تكليف وتسليم وتصحيح؛ ثم اختبار وحفظ إجابات وتسليم وقراءة النتيجة بعد النشر. | تتفق حالة العمل عند الطالب والمدرّس، ويحافظ انقطاع الاتصال أو تحديث الصفحة على الأثر الموثّق لكل خطوة. |
| مسجل ومسؤول قبول وقسم | طلب زائر ← مراجعة واعتماد ← سجل الطالب وبرنامجه وفصله؛ ثم تجربة التعديل والترفيع ببيانات قسمين. | تتطابق هوية الطالب وحالته في البوابة والتقارير، وتبقى السجلات الأخرى سليمة. |
| النتائج والشؤون العلمية وشؤون الطلاب | إدخال نتيجة ومراجعتها واعتمادها ونشرها، ثم طلب من الطالب ومعالجته وإشعاره. | يمكن تتبع كل انتقال وصاحبه، ويطابق عرض الطالب آخر قرار نافذ. |
| النظام والموارد البشرية والإدارة القسمية | إدارة حساب ودور أو طلب حذف، تحديث ملف موظف، ثم مقارنة القائمة والتقرير والطباعة داخل النطاق. | يتغير الوصول وفق القرار، وتطابق الأعداد والتصديرات السجلات المرئية للدور. |
| مستخدم البوابة المثبّتة | تثبيت PWA، تنزيل مورد مسموح، فتحه بعد قطع الشبكة، استعادة الاتصال، ثم تسجيل الخروج والدخول بحساب تجريبي آخر. | تظهر حالة الاتصال والتنزيل بوضوح، ويظل المحتوى الخاص محصورًا بصاحبه. |

### 5. التنفيذ والتسليم

1. **خط الأساس.** بعد تجهيز الاعتماديات وقاعدة PostgreSQL اختبارية، يُشغّل مسؤول الجودة `bash scripts/qa/run.sh docs/qa/evidence/review-2026-11-10/baseline lint migrations openapi typecheck backend-sqlite backend-pg frontend scripts lint-ui build seo e2e audit pip-audit`. يربط كل نتيجة بالنسخة ويميّز الفشل والمتخطى والمتعذر.
2. **توسيع التغطية.** يطابق المنفّذ الجرد مع اختبارات `fit` و`fit-signed-in` و`sweep` و`journeys` و`a11y` و`keyboard` و`pwa` في `e2e/tests`. يُملأ كل صف متبقٍ باختبار آلي أو فحص يدوي محدد. تُلتقط صور قبل الإصلاح وبعده بنفس البيانات والحجم.
3. **توثيق العيوب.** لكل عيب معرّف ونسخة ودور ومسار وخطوات ونتيجة متوقعة وفعلية ودليل منزوع البيانات الشخصية وخطورة ومسؤول. تُقدَّم أعطال سلامة الحساب والبيانات وتعطل الرحلات الأساسية على عيوب المحاذاة.
4. **قرار الإغلاق.** يُنشر جدول منفصل للموقع والبوابة ووحدات الخادم بعدد الحالات المخططة والمنفذة والناجحة والفاشلة والمتعذرة. تُذكر الأجهزة واللغات والأدوار التي جُرّبت فعليًا. يتطلب إعلان اكتمال الفحص نتيجة لكل صف منطبق، وإعادة الرحلات المتأثرة على نسخة الإصلاح. أي تعذر يبقى ظاهرًا مع أثره والمسؤول عن استكماله.

### المحور 2 — الصلاحيات مقابل roles-matrix (Opus)
